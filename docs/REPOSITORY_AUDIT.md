# Локальный аудит перед выпуском

Сканер: [Gitleaks 8.30.1](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1), официальный бинарный выпуск. Для использованного Darwin arm64-архива SHA-256: `b40ab0ae55c505963e365f271a8d3846efbc170aa17f2607f13df610a9aeb6a5`. Инструмент запускается локально и не входит в Pi Studio. Нужны Git, Node.js и авторизованный GitHub CLI для закрытого репозитория.

```sh
PI_STUDIO_GITLEAKS='/absolute/path/to/gitleaks' npm run audit:repository
PI_STUDIO_GITLEAKS='/absolute/path/to/gitleaks' npm run audit:release-assets
```

Первая команда получает ветки/теги без изменения рабочей ветки, проверяет всю достижимую историю, текущее дерево, локальные ZIP и метаданные всех страниц Releases. Вторая дополнительно скачивает и проверяет каждый опубликованный asset. Архивы обрабатываются по одному во временной папке и удаляются в `finally`; постоянных копий выпусков не создаётся. GitHub Actions остаются выключенными.

Отчёт: `artifacts/repository-security-audit-proof.json`. Сохраняются расположение, номер строки, правило, commit и результат разбора. Значения `Secret`/`Match`, фрагменты исходного секрета и сырые диагностические ответы не попадают в итоговый отчёт. Сырые результаты сканера редактируются через `--redact=100` и удаляются после обработки. Файлы студии, пользовательские credentials и рабочая установленная программа не входят в область сканирования.

## Что проверяется

- История: `gitleaks git --log-opts='--all --full-history'` по полученным веткам и тегам. Игнорирующие комментарии не применяются; используется отдельный пустой ignore-файл и стандартные правила сканера.
- Текущее дерево, включая неотслеживаемые и игнорируемые файлы вне явно исключённых корневых `node_modules`, `out`, `dist`, `.git`. Git проверяется через историю, собранные компоненты — внутри ZIP. Отдельно собираются подозрительные имена файлов, LFS pointers, symlinks и расположения абсолютных домашних путей.
- Локальные и опубликованные архивы: просмотр ZIP до двух уровней; размеры и SHA-256 опубликованных файлов сверяются с GitHub metadata, если digest предоставлен. Код из архивов не запускается.
- Метаданные всех релизов: body, названия и прочие поля ответа API также проходят сканирование.

SHA-256 не признаётся безопасной строкой только по длине. Ложное срабатывание допускается лишь после проверки, что это контрольная сумма указанного исходного файла либо известный immutable digest реестра старых шаблонов. Историческая контрольная сумма помечается отдельно и не доказывает актуальность старого QA-отчёта. Любой иной результат остаётся `needs-review`. Неоднозначные ZIP-записи и несовпадающие локальные заголовки не используются для такой классификации.

`allRequestedScansPassed` относится только к запрошенной области. Это не автоматическое принятие REL-02 и не доказательство отсутствия любых секретов. Сканер не проверяет внешние credential stores, недостижимые/dangling Git objects, визуальное содержимое всех изображений или права распространения материалов. LFS pointers и непрочитанные assets явно оставляют аудит незавершённым.

## Очистка и публикация

Результаты сначала разбираются: настоящие ключи требуют отзыва/замены владельцем, личные пути — отдельного решения, тестовые значения и digests — проверяемого объяснения. До удаления проверяются ссылки из исходников, тестов и документации.

Конкретный список файлов согласуется перед удалением. Переписывание опубликованной истории, force-push и удаление опубликованных release assets требуют отдельного явного согласования согласно [REL-02](../technical-spec/BACKLOG.md). Скрипт ничего не удаляет из репозитория/релизов и не меняет его видимость. Итоговая публичная поставка дополнительно проходит проверку подписей, прав распространения и нативную приёмку.
